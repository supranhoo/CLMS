# CLMS replica: test case matrix

Generated by `node scripts/test-matrix.mjs` from the server's own route list, the router in `src/App.jsx`, the route inventory and the test files. The full table is [test-case-matrix.csv](test-case-matrix.csv) (562 rows; open it in a spreadsheet and filter by Type, Area or Priority).

| Type | Cases | Automated by |
| --- | --- | --- |
| End-to-end workflows | 18 | named in each row (unit/contract tests, UI scenarios) |
| UI routes and variants | 85 | UI-02 route sweep for every route; 14 routes also have a scripted flow |
| API routes | 459 | SWEEP-02 (no session = 401), SWEEP-03 (never a 5xx), SWEEP-04 (unsupported = 501), and SWEEP-06 (administrator-only routes refused to ordinary users) for every route; 141 implemented routes are also named by a behavioural test |

API routes by status: implemented 305, rules-required 23, unsupported 131.

## What "automated" means here

- **SWEEP / AUD / ERD / HTML** are node:test suites in `tests/` (`npm test`, about 20 seconds, no browser).
- **UI-nn** are browser scenarios in `tests/ui/smoke.mjs` (`npm run test:ui`, about 3 minutes, needs Chromium).
- "Named by a behavioural test" is a text match: the route's action name appears in a test file. It shows where to look, not that every branch is covered. Server line coverage is measured separately (see READINESS.md).

## End-to-end workflows

### WF-01 Sign in, use the app, change password, sign out  (P0)

1. **Steps:** Sign in as demo; change nothing; register an ordinary user (admin); sign in as that user; change their password; confirm the message, the automatic sign-out and that the old password no longer works; sign out and replay the old token.
2. **Expected:** The new password works, the old one and the old token are refused.
3. **Automated:** UI-01; UI-08; UI-09; AUD-A06; AUD-A08; mock-api.test.

### WF-02 Account recovery  (P1)

1. **Steps:** Ask for a reset token for a user; read it from the local outbox (admin Development > Outbox); reset the password; sign in; try the token again.
2. **Expected:** The token works once, expires after 10 minutes, and three requests a day are allowed.
3. **Automated:** feature-workflows.test.

### WF-03 Lock-out and revoke  (P1)

1. **Steps:** Enter ten wrong passwords for one ID; deactivate a signed-in user; reset the data.
2. **Expected:** 429 for that ID only; a deactivated user's session ends at once; reset revokes every session.
3. **Automated:** AUD-A09; AUD-A07; SWEEP-07.

### WF-04 Roles and scope  (P0)

1. **Steps:** Register a user; assign business unit, contractor, department, location and a WRITE activity; sign in as that user.
2. **Expected:** The user sees and edits only workers in all four scopes; an empty assignment shows nothing; nested reports respect the scope.
3. **Automated:** AUD-A11; isolation.test; feature-workflows.test; UI-10.

### WF-05 Onboard a contractor and a worker  (P0)

1. **Steps:** Add a contractor; add a worker for that contractor with department, business unit and entity; edit the worker (pending); approve the change as an administrator.
2. **Expected:** The worker is created; the edit is applied only after approval and keeps any later change; unknown references are refused.
3. **Automated:** AUD-D01; AUD-D12; mock-api.test; UI-07.

### WF-06 Import workers from a workbook  (P1)

1. **Steps:** Open Development > Import; validate (dry run) a workbook with a bad row; fix it; commit; repeat the commit.
2. **Expected:** A bad row blocks the whole batch; a clean one inserts; a repeat is refused unless UPSERT is chosen; numeric cells become text.
3. **Automated:** import-workbook.test; feature-workflows.test.

### WF-07 Maintain master data  (P1)

1. **Steps:** Add, rename and delete a business unit, location, division, cost centre, city, shift group and holiday.
2. **Expected:** Duplicate keys and renames onto an existing key are refused; a record still used by workers, allocations or manpower cannot be deleted or re-keyed.
3. **Automated:** AUD-D02/D03; ERD-06.

### WF-08 Daily attendance  (P0)

1. **Steps:** Enter a manual muster mark (every mark in the list); upload a muster workbook; regularise a punch; approve it; try to edit it; withdraw the approval and edit.
2. **Expected:** Only listed marks are accepted; duplicates are refused with the reason; an approved regularisation is read-only until withdrawn.
3. **Automated:** attendance.test; AUD-D13; AUD-D14; UI-05; UI-14.

### WF-09 Punch import to processed attendance  (P1)

1. **Steps:** Upload punches; run Process attendance; read the job.
2. **Expected:** Punches are stored, first and last punch become IN/OUT, duplicates are counted, and no payable-day rule is applied (the screen says so).
3. **Automated:** attendance.test.

### WF-10 Approved manpower and requests  (P2)

1. **Steps:** Add approved manpower; add an on-duty request; approve and reject requests.
2. **Expected:** References are checked; overlapping requests are refused; approval stays "awaiting BFCL rules".
3. **Automated:** attendance.test; ERD-04.

### WF-11 Attendance reports and exports  (P0)

1. **Steps:** Export monthly attendance with times (single sheet and per contractor), monthly sheet (XLS) and daily register; try an empty range; try From after To.
2. **Expected:** Workbooks have the right columns and totals; an empty or failing export shows an error, never "printed successfully".
3. **Automated:** UI-12; UI-13; export-workbook.test; attendance.test.

### WF-12 Leave  (P0)

1. **Steps:** Add a leave; query the ledger; add a manual ledger row; delete the leave; try overlapping and over-long leave.
2. **Expected:** Balance moves by the days taken and returns on delete; overlap and days longer than the dates are refused; payroll posting answers 422.
3. **Automated:** leave-ledger.test; AUD-D04; payroll-posting.test.

### WF-13 Wage periods and rates  (P0)

1. **Steps:** Add a process month; add a fixed wage (billing type M, PF Y/N); add a second effective-dated rate; delete a month that has inputs.
2. **Expected:** Rates are effective-dated rows; a month with inputs cannot be deleted; PF/ESI/LWF accept Y or N only.
3. **Automated:** payroll.test; UI-06.

### WF-14 Wage inputs  (P0)

1. **Steps:** Add an earning, a deduction and an arrear; try duplicates; upload a workbook with one bad row; add a service-charge rule.
2. **Expected:** The code lists work in the screens; duplicates and bad rows are refused whole; amounts of 0 are allowed.
3. **Automated:** feature-workflows.test; payroll.test; UI-03; UI-04; UI-15.

### WF-15 Lock a period  (P0)

1. **Steps:** Lock a month for a contractor; try to edit its inputs and rates; unlock.
2. **Expected:** Edits answer 423 for that contractor only.
3. **Automated:** feature-workflows.test; payroll-posting.test.

### WF-16 Wage processing (not available)  (P1)

1. **Steps:** Try Process wages and every statement and report.
2. **Expected:** 422/501 with the missing BFCL rules; no figure is ever shown as a result.
3. **Automated:** payroll.test; SWEEP-04.

### WF-17 Compliance profiles  (P2)

1. **Steps:** Create a state profile; make it active; edit its rules with a stale version; open each compliance report.
2. **Expected:** Version conflicts answer 409; unverified status cannot be set to verified; reports show recorded data only.
3. **Automated:** feature-workflows.test.

### WF-18 Reset and repeat  (P0)

1. **Steps:** Reset the data (admin); sign in again; run a workflow twice.
2. **Expected:** Seed fixtures return, every session is revoked, the second run starts clean.
3. **Automated:** SWEEP-07; UI suite (fresh server per run).
